# 架构、Prompt 与成本审查

日期：2026-10-22。全部真实模型输入沿用上一轮已提交的虚构转录；没有上传真实用户档案、凭证或论文材料。对练使用的模型为 glm-5.3-flash，报告核对为 glm-5.3。

## 架构判断与交付

| 环节 | 审查结论 / 本轮处理 |
|---|---|
| 排程 | 按需触发；指定场景跳过处方 / 角色匹配，空背景跳过模型角色判断。保留现有本地检索，不新增 embedding 或服务端档案。 |
| 文字 / 3D 对练 | 完整历史保留承诺与责任；未展示前的有界修复有必要。3D 的 30 秒外层期限比通用任务期限严格，属于现有交互边界；未延长。 |
| 报告生成 → 核对 | 核对原来重复发送完整双语 corpus 对象。新增共享知识投影，只去掉另一种翻译、搜索标签等索引数据，保留全部已选来源内容与出处。全文转录、报告、现场观察和核对政策不删减。 |
| 反思 / 追问 | JSON 修复与语义修复曾嵌套，可能花掉最后一个调用位生成无法核对的草稿。改为同一层规划：至少剩两个调用位才生成；正常一生成一核对，有语义拒绝时可再做一轮；连续格式错误最多三次生成加一次核对。总逻辑调用仍四次，85 秒不变。 |
| Prompt | 把既有政策提为独立模块，修复反馈放在 user 上下文，system 前缀稳定。不声称因此命中了缓存。NPC 最后新提议不得写成双方已同意；需要逐项查找 learner 的同意证据。 |
| 核对格式 | 真实模型返回过精确路径 knowledge.whyThis，旧 enum 拒绝整份核对。仅把这个已知路径映射到 knowledge，完整保留拒绝与理由；未知路径仍拒绝。 |
| 共享预算 / BYOK | 保留 SDK 重试与匿名 Redis 原子预算。现有预算按 UTF-8 字节、输出上限、三次 SDK 尝试保守预留，不是实际消费；逻辑调用不等于 HTTP 次数。 |

没有调整模型档位、移除独立核对、提前展示未核对内容或裁掉历史。生成与核对使用同一模型仍可能相关漏判；更换模型需要单独盲评。超过 256 KB 的长上下文仍明确失败并保留本地档案，不能为降低成本直接丢掉早期证据。

## 可确定的输入减量

按同一转录、同一报告、同一检索集合重建前后请求，单位均为 UTF-8 字节：

| 固定样本 | 旧请求 | 新请求 | 减少 |
|---|---:|---:|---:|
| 文字中文 | 23,110 | 19,040 | 17.6% |
| 文字英文 | 25,150 | 20,944 | 16.7% |
| 3D 中文 | 26,756 | 22,171 | 17.1% |
| 3D 英文 | 27,449 | 23,178 | 15.6% |

原件：[assessment-request-sizes.json](./assessment-request-sizes.json)。当前语言的来源正文无损，源项数与顺序不变；其他上下文保持原样。这是报告核对请求规模的减量，不是整轮练习、实际 token、延迟或人民币费用的下降百分比。

## 撤回的实验

尝试把复盘政策从约 5.6 KB 压缩到约 4 KB。六个相同问题（四个事实追问、两个反思）使用固定转录，各进行一次真实运行：

| 版本 | 返回结果 | 逻辑调用总数 | 输入总字节 | 总耗时 |
|---|---:|---:|---:|---:|
| 原政策 baseline | 5/6 | 16 | 241,680 | 104.1 秒 |
| 短政策 compact-experiment | 5/6 | 19 | 259,637 | 115.2 秒 |

短政策单次输入更小，但修复增多，且人工发现一次把未接受的最后提议写成已达成。返回结果数只是任务结束数，不是内容正确率。小样本不足以估计发生率，但已不足以支持上线“更省钱”的结论，因此撤回政策缩写。

compact-followup 记录最后提议规则的早期复测，不是最终缩短版本上线。restored-policy 恢复原政策后六例只有 3/6 返回结果，保留空 evidence、坏 JSON、反思新台词等失败，没有把拒绝计作语义通过。随后将修复规划改为每轮预留核对槽位，budget-followup 复测两个英文问题：办公室事实问题完成，关系问题仍失败；确定性测试覆盖两次格式失败后第三次生成加核对成功的四次调用路径。不能据此声称全面提高生成成功率。

## 真实核对与剩余边界

- assessment-comparison 对四份历史报告分别用完整来源和投影来源各核对一次（顺序按语言交替）。七次产生有效结论；中文 3D 投影首次返回 knowledge.whyThis 导致旧 schema 失败。修复后 assessment-followup 的完整 / 投影两次均产生有效结论。模型还会误报连续引文，所有原始返回保留；“核对返回有效”不等于报告已经完美。
- restored-policy 中四个负例均被拒绝：新增发送承诺、无条件提前通知、遗漏后续责任归属，以及未接受的最后方案被写成双方同意。新增原件见 unaccepted-final-proposal.json；其他三个沿用上一轮原件。budget-followup 另记录最终代码的反例复测。
- 程序检查：101 项 core + 256 项 dinner，全量 lint / 类型检查通过；23 项复盘契约检查通过；正式构建通过。UI、接口和存储契约未改，本轮没有把任务脚本冒充浏览器或生产验收。
- 真实模型仍可能生成非法结构、漏判或误拒；尤其英文反思，需要扩大新转录 / 不同供应商的盲评。现有拒绝路径保留记录、不交付草稿，问题已记入 backlog。没有实际 usage / 缓存账单，不能估算金额节省。

## 复现

在 app/ 配好自己的模型环境。后两项会付费调用真实模型，输出目录必须不存在；脚本拒绝覆盖旧证据。

```sh
pnpm exec tsx scripts/check-prompt-context.ts
PROMPT_COST_DIR=/tmp/new-prompt-comparison node --env-file=.env.local --import tsx scripts/check-prompt-cost-live.ts
ASSESSMENT_CONTEXT_DIR=/tmp/new-assessment-comparison node --env-file=.env.local --import tsx scripts/check-assessment-context-live.ts
```

可用 PROMPT_COST_CASE 或 ASSESSMENT_CONTEXT_CASE 选择样本。脚本保留可见模型输出、逻辑调用、请求字节和耗时，不保存密钥、思考内容或私有账单。baseline 与实验目录是开发阶段的原件；上述命令重跑的是最终实现，不能称为重现旧模型的确定性输出。
