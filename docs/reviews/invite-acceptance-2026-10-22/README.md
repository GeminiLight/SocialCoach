# 分享邀请独立验收（2026-10-22）

复核版本化公开邀请的生成、接收、练习与复盘流程。浏览器使用合成档案和模型响应，阻断真实模型与统计请求；本轮不评价真实模型内容质量。

## 发现与修复

- 接收者已保存的语言与邀请语言不同，模型提示、接入弹窗、禁用按钮提示和反馈界面会混用语言。邀请 URL 应控制公共界面，访问和查看弹窗不改写原有档案。首次访问的同源问题由邀请发布修复一起处理。
- 无法读取档案时，恢复界面也应跟随邀请语言；切换语言只切换当前邀请 URL，不覆盖损坏档案。保留备份、重试与明确确认后的重置流程。

## 验收

- `check-invite-language.ts`：中→英、英→中，模型提示 / 按钮说明 / 接入弹窗及关闭按钮 / 反馈弹窗 / 未知版本；完整原始档案逐字不变。正式构建中损坏档案的邀请页和普通恢复页均能中英切换，原始内容不变。见 `language.json`。
- `check-invite-browser.ts`：中英 × 明暗 × 375 / 1440 共 8 组；两种目的地二维码解码、复制、隐私排除、新接收者、续练、复盘均通过，每组 axe 问题 0。见 `browser.json`。
- `check-invite-recovery.ts`：剪贴板拒绝、系统分享取消 / 不支持 / 失败、图片生成失败与重试、快速切换、键盘焦点、连续点击、返回续练、旧档案保留、未知版本、损坏档案与 360 / 540px 二维码解码通过。开发环境单独完整运行通过；其他运行及正式构建上的 CLI 自动化曾在导航处回到 `about:blank` 或超时，不能把它们记为通过。补充了失败 URL / 快照诊断，并改为页面完成初始化后才写入测试档案。见 `recovery.json`。
- 独立 Chromium 复验正式构建，连续 3 组快速双击 → 浏览器返回 → 继续同一场 → 刷新全部通过，始终只有一场新练习，姓名保留，页面错误 0；没有复现上述空白页问题。见 `navigation.json`，可运行 `navigation-check.cjs` 复验（需本地 Playwright，或通过 `PLAYWRIGHT_MODULE` 指向已安装模块，服务端口 4339）。
- 本地质量检查：123 项核心 + 256 项饭局测试通过，lint、类型检查和正式构建通过。

手机系统分享与实际社交 App 内扫码仍需真机验证；桌面浏览器的模拟分享结果不代表所有移动平台。
