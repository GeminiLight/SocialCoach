# 本次练习的复盘 AI 助手

需求：用户看到复盘中的「自我暴露」等概念时，可以直接问是什么意思、这次怎么用，再连续追问边界与具体说法。

## 体验与范围

- 报告阅读导航提供「复盘助手」入口；知识卡片展开后提供「问问如何用」，带入该知识标题并聚焦输入，不自动调用模型。
- 助手在知识卡片之后、固定反思题之前，提供解释概念、换一种说法、下次怎么用三个可编辑的问题起点。
- 支持多轮问答，回答按用户原话 → 解释 → 明确标注的示范 → 已有知识依据排列。用户可以质疑原报告；不能改分或改写真实转录。
- 单场历史存在 `Session.debriefChat?`；旧档案无需迁移。成功后一次写入完整问答，失败 / 停止保留问题；草稿使用标签页存储。全部问答随既有 JSON 导出，重置沿用本地清理规则。

## 模型与数据边界

`buildDebriefInput()` 只发送场景标题、公开背景和角色、真实双方转录、报告的文字结论、最近六组问答和当前问题。排除 NPC hidden / stance / personality、成功 / 失败模板、教练提示、档案和评分增量。完整历史仍保存在设备。

共享 `runDebriefChat()` 同时服务部署模型和 BYOK，不在两者之间自动回退。每次最多检索四条理论、两条案例：保留报告引用，并用中英文标题 / 关键词匹配当前问题与上次问答，覆盖中文不分词的「自我暴露」查询。结构 / 引文 / 来源校验失败最多重新生成一次，再校验；JSON 解析沿用既有一次重试。解析错误日志不保留模型正文。

回答用 `jsonCall()`，通过结构、连续原话与检索来源 ID 校验后才呈现。有 learner 发言时必须引用其中真实片段；没有时只允许空 evidence、概念指导，不评价用户表现。引用来源只解析语料里的作者 / 书名 / 链接，不接受模型生成的 URL。新个人事实必须用条件句提出；没有后续 NPC 回复不能断言建议已生效。语义解释仍是模型推断，结构校验不能保证每句话都正确。

`POST /api/debrief-chat` 返回 JSON，使用 fast 模型、2400 输出 token、60 秒服务端时限及既有速率限制。问题上限 1000 字符、最多 100 条发言、请求体上限 160 KB、最近六组问答。客户端等待 55 秒；停止和离开后迟到结果不能写回。失败统计只记录 task / 状态 / 类型，不上传问答内容。
