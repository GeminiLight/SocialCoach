# SocialCoach 3D 接入主版本

用户于 2026-10-03 将此前「独立子仓库」的边界改为「接入主版本」。导入独立原型 `GeminiLight/SocialCoach-3D` 的 `60cd20a`，保留原仓库与本地数据；主站可独立构建，不依赖子目录、其开发服务器或 iframe。

## 入口与边界

- 主站内 `/3d` 独立全视窗页面。首页卡片、桌面导航与首次欢迎页入口均能进入；3D 顶部返回首页，未完成主站设置者返回欢迎页。
- 主站已有档案在首页第一次看到本版本公告，可关闭、Esc 或点击背景退出。`socialcoach.3d-launch.v1` 标记已展示；有未完练习 / 待复盘、档案恢复或模型弹窗时不抢占。直接进入 3D 也记录已体验，返回不再推送。
- WebGL、Three.js 与 3D 内容按页面加载；常驻入口不预取 3D。手机维持原来的五个主导航项目。
- 第一 / 第三人称、自由移动、关注人物、邀请、集体举杯、茶回应、手机 / 合影等交互沿用原型。NPC 不跟随玩家擅自离席。当前仍为程序建模，不能宣称真人或照片级写实。
- 浏览器语音先生成草稿，用户确认发送；识别可能使用浏览器厂商的联网服务。应用不保存音频。

## 数据与模型

- 3D 存档仍为 `socialcoach-dinner-v1`，独立于主档案，保存四回合对话、草稿、视角、位置与饭桌事件；主设置导出包括 `dinner3d`，不含模型密钥。主设置「清除所有数据」也清除此存档。主档案的损坏恢复不清除独立 3D 存档。
- 同源之后仍不自动迁移此前 `4318` 等不同源的存档；原独立体验与存档保留。
- 沿用 `/api/health` 和现有部署模型。共享额度走 `/api/dinner/direct`，采用主站限流；自带模型通过同一个任务在浏览器调用供应商，密钥不经过主服务器。未配置时明确标示剧情模式，模型失败不静默替换为剧本。
- 共用 `jsonCall()`，不使用网关不支持的结构化 SDK 格式。校验请求 / 对话顺序 / 当前场景人物 / 事件与回合 / 输出完整演员表。30 秒服务器限时，35 秒客户端限时，取消信号传给 SDK。失败保留输入。
- 主站纸面与 3D 暗色包厢样式隔离：选择器 `.dinner-experience`，色值只在 `app/src/app/globals.css`，变量前缀 `--dinner-*`。优化后的 Lab / 原始 OKLCH 都转换到 WebGL 可读的 sRGB。

## Fiction

三个场景是本项目原创虚构剧情，沿用原型出处声明，不能作为真实案例或研究证据：

1. 职场：望江阁项目庆功宴。陈总劝酒、林姐追问交付、小周提供有限支持；举茶与不喝酒都不自动解决项目压力。
2. 家庭：亲戚饭桌的婚事追问。梅姨递手机、母亲施压、父亲想让饭继续；接手机不等于同意介绍或约会。
3. 学校：竞赛庆功与贡献归属。许队保护队长功劳、悦悦谈设计、小凯谈代码记录；合影不等于贡献已获承认。

源代码中的 `source.path` 指向此节。任何复盘先展示本局实际发言与动作证据，不产生无转录的评价。
