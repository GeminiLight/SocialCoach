# 3D 入席、群体回应与沉浸收尾

已在主站 `/3d` 完成。原独立演示仓库不作为同步交付条件。

开局给具体压力和立即接话入口。用户可查阅文案 / 任务 / 测试资料，也能选择开口、沉默、拒绝、找旁人或走动。至少一位 NPC 的不同利益应能推进冲突，插话可省略，不能把每一轮做成三人轮番附和。

## 边界

- 同桌最多一条可选短插话，主回复先回答当前用户。插话也进入历史 / 模型上下文；保持同一玩家回合。
- 开局資料是固定的原始证据，后续约定在原话中确认，不做假实时文档或后台审批。
- 可选浏览器朗读与现场说话动作按序；收音、暂停、页面隐藏、取消、卸载要清理。浏览器缺少语音能力时保留字幕。
- 动作时间只影响显示：不强迫喝酒，不自动接受见面或拍照。等待时放下杯子；晚回应平滑继续。
- 不新增账号 / 服务端存储 / 外部人物素材 / 提交计时压力。保持主站模型、BYOK 和请求故障恢复。

## Fiction

六份开局资料由本项目原创虚构，不是现实饭局调查、专家策略或真人故事。既有工作线的两个失败测试、家庭线的介绍 / 工作消息、学校线的代码 / 设计 / 汇报分工来自 `story.ts` 的相同原创设定。本轮将学校尚未发布的草稿明确为“这次主要由我带队，队友负责执行。感谢大家。”；新增句子只是可核对的冲突道具，不是训练建议。不得用资料推断用户性别、工资、关系或已同意事项。

## 验收

1. 三桌六个开局各跑五个真实自由输入回合，覆盖拒酒 / 怒气修复 / 隐私 / 抢功 / 拒绝分工，并人工阅读三轮结果。
2. 定向复测明确拒绝、时间转述、隐私权限和拍照 / 发布确认。记录结构通过与语义局限。
3. 正式构建验证手机 / 桌面、资料、历史、刷新草稿、第一 / 第三人称、等待时起身与语音互斥。
4. 角色校验、短句修复、历史顺序、播放暂停和晚举杯检查通过。细节见 [验收](../../reviews/review-2026-10-03-3d-immersion.md)。
