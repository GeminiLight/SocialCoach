## 当前最大问题与本轮证据

### 一份坏 3D 原件会挡住整份健康文字档案

本轮在当前源码运行既有最小重放，使用审查目录中的虚构档案，无真实用户记录、凭证或模型请求：

```json
{"case":"healthy main archive with exported unreadable dinner wrapper","main_sessions_restorable":1,"when_unreadable_dinner_exported":"backup-dinner"}
```

健康主档案本身可解析出一场练习；加入系统自身可能导出的 `dinner3d.unreadable` 包装后，`decodeBackup()` 抛出 `backup-dinner`。因此“有导出”还不能保证备份在局部损坏时可恢复。→ [反例与虚构样本](../../../docs/reviews/whole-repo-2026-10-07/reproduce-backup.ts)、[原始发现 R4](../../reviews/review-2026-10-07-whole-repo.md#r4损坏-3d-原件阻断健康档案恢复)。

另两项沿用[10-07 实际网页复现](../../reviews/review-2026-10-07-whole-repo.md)：旧 3D 标签切视角覆盖新标签草稿；清除所有数据后，旧窗口打开接入弹窗将已清除的虚构密钥写回。核对审查基线 `a1b10f1` 至当前 `HEAD`，`DinnerApp.tsx`、`storage.ts`、`byok.ts`、`backup.ts` 均无差异。本轮重新读取了写入路径；这两项未重新做网页操作，未测真实发生率，也未发现凭证外传证据。

### 需求与使用数据仍不可读取

尝试以飞书用户身份定位 SocialCoach 多维表格，返回 `authentication / token_missing`。本轮未取得反馈记录或匿名事件，未切换应用身份、发起登录或修改权限。开始率、完成率、七日再练、真实等待与调用费用均无法报告。

当前 `retention.ts` 按设备首见日统计后续日期的文字 `session_start`，不读取 3D `practice_stage`；这不等同于“首次有效练习后七日内再次独立练习”。后续先补齐读取与核对口径：按部署分别看，区分文字 / 3D / 自定义、默认模型 / BYOK；同局续聊与重复复盘去重，满七日队列再比较，设备不当作真人。当前 schema 含独立 `practice` 字段，不代表实际线上记录已完整、可正确关联。

## 本周推荐与最小边界

选 **A**，因为它有今天可重复的失败证据，且会破坏产品承诺的本地档案、引用证据与恢复能力。B 的生成状态问题继续保留优先级；1 亿配置缓解了当次阻塞。C 有价值，但主动重练需求尚待观察。

拟定顺序：先用虚构数据重做跨窗口覆盖 / 清除反例，再修独立写入和删除失效；随后隔离恢复主档案与坏 3D 原件。只在主仓库实现，复用文字档案已具备的保护原则；不合并两份 schema、不引入账号或云端练习档案。独立演示仓库同步不作为交付条件。

### 下一步验收

1. A / B 两页交替输入；关闭新页后，旧页切视角、移动、刷新均不能覆盖新原话或草稿。冲突可导出两份，恢复选择明确。
2. 实际清除后，旧页开关接入窗、切语言、保存旧表单均不能恢复密钥；只用关闭状态的虚构凭证，核对旧配置不可再发起请求。
3. 备份往返覆盖无 3D、健康 3D、损坏 JSON 包装、合法 JSON 坏 schema：健康主档案可预览和恢复，坏 3D 原件保留并可下载。
4. 无 Web Locks 回退、写入配额失败、导入冲突、刷新 / 关闭的状态边界；中英文提示与现有单页正常保存一起回归。真实手机另列实际结果。
5. 交付记录分开报告实现、回归、实际网页和发布状态。下周只在有新增证据时把本项标为完成；否则回看受阻原因。

**可能推翻本次推荐的证据：** 如果当前生产已存在不在本地记录里的修复，并能用同一组反例证明跨窗口、删除与局部备份恢复均正常，应降级 A；若同时出现默认模式大范围无法开练的最新证据，则 B 提升为首要重点。
