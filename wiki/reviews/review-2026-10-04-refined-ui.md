# SocialCoach 克制界面与练习优先级评审

**结论：本轮交付通过。** 原界面的主要问题是视觉语义重叠：操作按钮、分类、技能标签、选中导航都使用胶囊和色块；首页 3D 推广在常规练习之前。此次以暖纸、墨色、开放文字排版和细线组织信息，保留证据批注、角色辨识、进度和知识出处。

设计评分 **C+ → B+**，通用装饰 / AI 模板感评分 **C → A-**（A 最好）。这些是基于实际截图的设计判断，不是用户研究或量化的满意度提升。实体设备与长期使用仍沿用现有待验收项。

## 五项具体处理

| 项目 | 原问题 | 已交付 |
|---|---|---|
| FINDING-001 共享视觉语法 | 导航同时用粉彩底、彩色图标、粗体和小圆点；主按钮 / 分类均胶囊 | 中性选中态、克制线性图标；操作 6px 圆角，内容 10px，弹窗 14px；墨色主动作；216px 侧栏、1280px 内容上限 |
| FINDING-002 场景选择 | 390px 首屏被介绍、推广卡和三组筛选占满；推荐再重复彩色图标与技能胶囊 | 搜索常驻、次级筛选单入口；文字情境导航；推荐细线三列 / 手机纵向行；目录序号与普通元信息，完整首项可见 |
| FINDING-003 首页内容优先级 | 大型 3D 推广占据桌面约 500px，手机把常规练习挤出首屏；次级 3D 链接在深底上对比不足 | 练习内容排在 3D 前；桌面 3D 横向布局；全部入口链接使用局部 dinner 前景与边框色 |
| FINDING-004 阅读与复盘 | 知识目录重复框线 / 类型图标，正文铺色底，助手有装饰色圈和独立大卡片 | 连续文字目录、开放阅读区、细线与留白；助手直接承接复盘；资料与偏好控件共享几何语言 |
| FINDING-005 首页状态优先级 | 不同首页状态需要不同主动作，统一填色会让「继续」与新任务争抢 | 有未完成练习时只突出继续；无今日任务时真实排练在前；已有今日任务时显示推荐；文档顺序与视觉 / 焦点顺序一致 |

- 九页 × 桌面 1440 / 手机 390 的实际浏览器截图，检查排版、内容密度和横向溢出。页面为今日、练习场、真实排练、知识、成长、设置、准备、对话、复盘。
- 新增 `app/scripts/check-refined-workspace-browser.ts`：**69 项通过**。覆盖组合筛选、收起后的条件摘要、刷新恢复、预览后返回原 URL、空结果清空与焦点、加载更多、首页不同状态的主动作。
- 工作区覆盖中英 × 明暗 × 360 / 1440，另测 820 平板与 1920 宽屏；arena、知识、3D 入口自动 WCAG A / AA 扫描 **24 组无违规**；筛选触区至少 44px。

- 正式构建、TypeScript、改动文件 ESLint 与 diff 空白检查通过。
- 所有模型响应来自本地拦截 / 夹具；不使用付费生成、不写真实用户档案、不向反馈与统计服务发送验收数据。截图中的练习内容用于界面验证，不能作为模型质量证据。

## 取舍与边界

- 保留人物头像、头像选择、开关、沟通质量星数与能力雷达；它们承担身份、状态或数据表达，不随装饰统一移除。
- 不变更 NPC 行为、评分、语料、API、双语主句及设备存储。没有引入账户、服务端练习存储、新字体或生成图片。
- 这轮覆盖主站共享 UI 与 3D 入口；3D 场景内的游戏 HUD、人物和剧情沿用已验证实现。
- 静态物料与实体 iOS / Android 的待验收项继续保留在 backlog，不将模拟视口当作实体设备验证。
