# 3D 电梯口 / 办公室体验验收

主站增加两个独立空间、六位新人物和四个原创开局。范围与原创出处见[方案](../archive/specs/spec-3d-places.md)。现有模型 / BYOK、可编辑语音草稿、完整历史和本地档案沿用主站；没有新账号或服务端对话存储。

## 三轮发现与修正

1. 初轮：按钮可远程开关门；第一人称人物视野过窄；任务 / 汇报事实容易由模型补写。改为先走近再按按钮，调整相机与人物位置，分离四开局事实。
2. 复测：进入轿厢关门后缺少内侧面板；办公室途中路线需要绕桌；模型曾称玩家未解释风险，或添加不存在的交接清单。增加内侧按钮、门防夹、导航采样检查，并固定交接材料 / 客户邮件，强调已说出的风险与发言人的归属。
3. 收尾：从首页再次进入新场景入口时，客户端路由可能恢复旧场景却忽略预选参数。新场景入口改用完整页面导航，随后消费一次参数；明确开始新局之前保留旧记录。走近电梯按钮增加取消入口；电梯动作标题不再始终声称门开着。汇报开场未点击开始时，相机也朝向实际发言的宁姐，只调整视线，不推进动作或时间。已打开的局不会在刷新后被新入口悄悄覆盖。

连续更换本地正式构建时，旧 Service Worker 可缓存曾返回错误的静态资源，导致同一预览端口首页空白；使用新的本地 origin 验证正式构建。该缓存策略的后续加固记录在 backlog，不把本地缓存状态等同于线上发布结果。

## 证据与边界

- `npm run test:dinner`：117 项通过，含旧饭局、24 回合预算与新空间。覆盖导航、门口防夹、暂停、轿厢内开门退出、返回姿态、固定 NPC、旧 v1 档案和非法跨场景状态。
- 本轮真实模型脚本共 140 条成功回复：初轮 64、修正后 64、最终事实 / 记忆专项 12。四开局分别包含 12 回合中文与 4 回合英文；[保存的 76 条修正后回放](../../docs/reviews/3d-places-2026-10-03/model-replays.json)包含前一轮长轨迹与最终专项，不能混称全部为同一最终版本。
- 结构校验包括当前输入引文、角色、长度、支持的动作与事件。专项实测包含：走到旁边不自动私密、道歉不证明事故原因、看任务单不答应接活、抬手不自动获得同意、既有时间 / 交接材料 / 客户要求与风险不被改写。
- 浏览器实际调用通过，主管只把玩家明确答应的最后检查算作承诺，瑞瑞提出自己的范围；未替宁姐决定。模型语义仍依赖理解，样本不证明所有自由输入都正确。
- 桌面 1280×720、窄屏 390×844 及中英检查；图像证据在[目录](../../docs/reviews/3d-places-2026-10-03/)。窄屏为浏览器模拟，不等于真实手机键盘 / 语音验证。
- 电梯明确为同层停靠场景，人物为程序建模。没有宣称电梯行驶、物理拟真、写实人物资产或真实用户测试。

复测脚本：在 `app/` 使用 `node --env-file=.env.local --import tsx scripts/check-places-live.ts`，之后运行同方式的 `scripts/check-places-followup.ts`。专项脚本也接受指定的长轨迹 JSON 路径；不使用真实个人信息。

## 八个体验视角

| 视角 | 结论与证据 |
|---|---|
| 层级 / 导航 | 场景、压力开场和开口为主；资料 / 历史按需打开，新场景在主页有直接入口。 |
| 视觉与产品辨识 | 两空间使用办公家具、金属电梯、白板及路牌；六人有独立体型、服装、发型与脸部参数。没有装饰性渐变宣传模板。 |
| 操作 / 反馈 | 面板必须走近；有行走、开门、关门、防夹与取消反馈；查看资料不生成同意台词。 |
| 可访问性 | 场景物件另有语义按钮；可见键盘焦点与双语名称；主要新增操作至少 44px，人物移动与视角沿用减弱动效支持。 |
| 文案 | 使用电梯口、工位、走近开门等实际行为标签；不再称新空间为饭桌，不夸大可玩内容。 |
| 响应式 | 桌面与 390px 下保留资料、动作、输入、历史和视角；真实设备另列后续验收。 |
| 性能 / 等待 | 3D 按需加载；模型等待有明确状态，继续探索，失败保留草稿；旧饭桌加载路径不变。 |
| 产品一致性 | NPC 有自己的利益，动作不替玩家承诺；原创出处可查，记录仍留在设备上。 |

## 十二项交付门槛

| # | 门槛 | 状态 | 证据 |
|---|---|---|---|
| 1 | 主任务清晰 | PASS | 标题、冲突台词、开始接话明确可练内容；为启发式评审，未计时测试真人。 |
| 2 | 主操作突出 | PASS | 开始接话 / 开口沿用主按钮，资料与移动为次级操作。 |
| 3 | 状态完整 | PASS | 默认、等待、禁用、错误恢复、移动、门动画、防夹、取消均有状态；无无效自动选项。 |
| 4 | 对比度 | PASS | 主要文本沿用高对比墨色 / 深色 scrim，按钮有深色底；电梯状态文字使用主文本色与实色深底（实际 CSS Lab 亮度换算约 16.4:1），避免金属墙面影响可读性；不声称 3D 纹理为网页 AA 文本。 |
| 5 | 焦点可见 | PASS | 键盘 Tab 到看向发言人有 2px 轮廓、4px 偏移；模态窗有焦点约束与 Escape。 |
| 6 | 错误可恢复 | PASS | 共用模型错误 / 损坏档案恢复；请求失败不写入回合，原草稿保留。 |
| 7 | 窄屏可用 | PASS | 390×844 检查无横向溢出，资料与历史可关闭，人物视角可切换。 |
| 8 | 不套通用 AI 模板 | PASS | 真实渲染空间是主体，场景文字短，非功能卡片堆叠。 |
| 9 | 无诱导陷阱 | PASS | 无假倒计时 / 假同意；点击新入口不覆盖旧记录，明确开新局才替换。 |
| 10 | 操作有反馈 | PASS | 所有物理选择实际到达后记录；开关门与防夹、走近 / 取消有状态文字。 |
| 11 | 触区足够 | PASS | 新场景入口、门控制与办公室操作至少 44px；3D 物件有等价界面按钮。 |
| 12 | 标签诚实 | PASS | 电梯停层，走近按钮，四开局资料独立；未把动作、礼貌或看资料当作结果。 |

参考：[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[可见焦点说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)。44px 是本次界面目标，不把它与 WCAG 最低 24px 要求混为一谈。
