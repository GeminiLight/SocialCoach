# 3D 入席与群体回应验收

本轮把“怎样让饭桌更值得玩”落实为可看到、可追问、有不同利益的现场变化。主站是开发主线；没有新建另一套 3D 实现。采用 super-product-ux 的八视角、十二门槛，完成三轮检查与修复。

## 校准依据

从作者的 [Façade 论文](https://cdn.aaai.org/ojs/18733/18733-52-22385-1-10-20210928.pdf) 中推导本轮取舍：人物需要协调回应并保留各自立场，不只是轮流显示一句话。结合 [Papers, Please 官方资料](https://www.papersplea.se/presskit/) 推导：固定场景里可以通过可核对资料和决定的后果产生变化。这是设计判断，不能当作这款产品已获得同样可玩性的证据。触控检查参考 [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)，本项目操作区采用更宽裕的 44px 高度。

## 发现与修复

| 严重性 | 实际问题 | 处理 |
|---|---|---|
| High | 请求模型时全桌呼吸 / 眨眼冻结，等待时不能起身 | 请求等待保留角色独立动作和探索；发言快照不随之后移动而改写；面板 / 隐藏标签页才暂停 |
| High | 久等一直举杯，普通模型举杯也永久停住 | 物理举杯错开升落；长等待自然放下；晚回应从实际放下位置再抬起；普通举杯亦有有限收尾 |
| High | NPC 把明确不相亲转述成“没定”，把十点复测改为明晚 | 强化拒绝范围、时间和未知信息边界；单独提供用户原话证据；定向真实追问复测，仍不宣称语义保证 |
| Medium | 另外两人像无声背景，所有意见都靠主角传递 | 同一模型回合可带一句另一人的具体利益 / 限制 / 事实；角色校验、限长、历史 / 存档原样保存 |
| Medium | “文案在手机里”却无法查看 | 六份真实可打开的原创开局资料，与模型事实一致；明确后续约定以原话为准 |
| Medium | 手机前景餐具压住字幕对比度 | 随对话区实际高度压暗背景；姓名小暗底；没有改用遮满画面的聊天窗 |
| Medium | 说话、声音开关和举杯声音没有共同收尾 | 主句 / 插话有限按序播放；浏览器朗读可选；收音取消朗读，朗读压低环境声；移除声音开关带来的假碰杯 |
| Low | 初次入席还要选择回合长度 | 默认 12 回合、可续聊；长度选择保留在换桌面板，开局一个“开始接话” |

## 三轮模拟

全部为合成用户输入，调用配置中的真实模型端点；没有用固定回复冒充模型。每轮六开局各五次自由输入，共 90 次请求；另用完整此前历史做 8 次针对追问。98 次均返回有效回复，逐条人工阅读，不把 HTTP 成功等同于剧情成功。

| 轮次 | 请求 | 有旁人插话 | 结果与继续处理 |
|---|---:|---:|---|
| 原版本 | 30 | 0 | 暴露台词循环 / 资料不可查阅 / 拒绝被淡化；全部 200，耗时 2.8–7.8s |
| 第一轮修复 | 30 | 18 | 旁人出现不同利益；仍发现不相亲变待答复、凭空复现次数及用户性别；耗时 2.5–9.5s |
| 第二轮修复 | 30 | 23 | 群体反应明显增加；仍发现十点被改为明晚；耗时 3.2–5.3s，继续加用户原话证据 |
| 最终针对追问 | 8 | 4 | 保留十点复测、不相亲、转述权限及未确认拍照 / 发布；耗时 2.2–5.5s |

示例：拒绝饮酒后林姐继续问交付、小周说明自己负责的失败测试；隐私桌大姨要求亲戚间“有个交代”，不会全员立刻接受；抢功桌小月要求设计单独署名，许学长仍保留汇报负责人；分工桌其他人只能给自己的条件。针对追问中，大姨明确说“是‘不想相亲’，不是‘没定’”，小周保留“明天十点…结果出来再谈日期”。这些是当次转录，不能当作所有输入的结果保证。

完整可复核原话：[98 次模拟转录](../../docs/reviews/3d-immersion-2026-10-03/simulations.json)。可重复的六场模拟脚本为 `app/scripts/check-dinner-immersion-live.ts`，每次 30 个请求，沿用路由限流；需人工检查含义，不跳过错误、不改请求 IP 绕过限制。

## 八视角

| 视角 | 判断 |
|---|---|
| 层级 / 信息 | 冲突原话为主；资料 / 历史次级；开始和开口为主要动作；长度不占开场 |
| 视觉品味 | 暖色包厢、真实饭桌素材和简洁现场字幕；保留不同桌人物、没有通用 SaaS 卡片 / 装饰闪光 |
| 交互 | 等回复有明确状态且仍能起身；资料 / 历史可退回；杯子 / 说话有收尾；没有自动替人同意 |
| 可访问性 | 操作有名称、44px 目标、键盘焦点；字幕常驻；已有减少动效行为继续保留 |
| 文案 | 具体压力、资料原句与独立署名；声音能力边界在玩法说明中；不以好态度自动换来成功 |
| 响应式 | 正式构建 390×844 操作区无横向溢出，资料 / 历史可读；1280×720 现场与视角切换 |
| 性能感受 | 没有新远程人物资源；模型等待不卡死场景；有限播放每帧只推时间、仅阶段变化更新 React |
| 品牌 / 信任 | 名称仍为 SocialCoach；资料标注原创虚构；开局材料不假装自动更新；用户数据仍只在设备上 |

## 正式构建与边界

106 项饭局检查、改动文件 / 模拟脚本 ESLint、TypeScript、Next 正式构建通过。新增检查验证旁人不能冒充主角 / 跨桌、存档回合不变、转录先后、暂停 / 隐藏时间不跳跃、晚举杯平滑和旁人超长修复。

浏览器在本地正式构建完成：390×844 首次入席；开启声音后启动收音，NPC 立即停止说话，取消保留草稿；请求中起身；真实模型回复后旁人插话进入历史；打开历史、返回、刷新均保留草稿和原话；第一 / 第三人称及自由环顾检查。没有把麦克风权限等待当作已完成真人语音识别，亦未验证所有设备的朗读音色质量。

截图：[手机开场](../../docs/reviews/3d-immersion-2026-10-03/mobile-opening.png)、[手机入席](../../docs/reviews/3d-immersion-2026-10-03/mobile-playing.png)、[手机历史](../../docs/reviews/3d-immersion-2026-10-03/mobile-history.png)、[桌面现场](../../docs/reviews/3d-immersion-2026-10-03/desktop-playing.png)。均为本地正式构建。

验收结论：这轮修复达到可发布范围。人物仍是风格化程序资产；无真人试玩留存数据，不能声称“任何用户都会觉得有趣”或“极致真实”。模型仍可能误读、朗读能力依设备不同；这些保留在 backlog。独立演示仓库未同步。本轮未适配 ModelScope 镜像的旧模型集成，保留其已验证版本，主站交付优先。

Skill evolution: no update needed。现有 super-product-ux 的多视角与门槛足够，本项目增加真实多轮语义复核和有限动作收尾的可复核转录。
