# 3D 性能优化验收（2026-10-03）

主站 `/3d` 降低持续绘制、标签布局测量和本地写入的开销，保留人物几何、移动、完整转录与模型校验。独立演示仓库未同步。

## 实测

基线为 `9c049ab`，优化版为本轮静态合批、布局缓存、按需暂停和剧情 UI 更新。两者均为本地 Next.js 生产构建，在同一台电脑、Codex 内置浏览器、1280 × 720 下测量。仪表每 3 秒读取一次 Three.js 计数，记录布局读取、本地写入与实际渲染帧数。[原始数据](./assets/2026-10-03-3d-performance.json) 保留不同阶段的样本。

| 工况 / 指标 | 基线 | 优化版 | 结论 |
|---|---:|---:|---|
| 饭桌开场每帧绘制次数 | 614 | 289 | 减少 52.9% |
| 练习早期每帧绘制次数 | 614 | 287 | 减少 53.3% |
| 练习早期布局读取 / 秒 | 563.2 | 0 | 稳态不再逐帧测量；布局变化时重新测量 |
| 历史面板开启后渲染帧 / 秒 | 120 | 0 | 场景稳定后停止持续绘制 |
| 练习早期本地写入 / 秒 | 7.3 | 1.3 | 动画时间不再驱动全量存档 |
| 开场可见三角面 | 554,258 | 563,938 | 几何未简化；合批使视锥裁剪粒度变粗，约多 1.7% |

这些是具体渲染工作量的变化，**不是帧率提升 53%**。高刷新率电脑的活跃帧率样本为基线 112.6、优化版 103.4；多个 WebGL 标签页及采样时机影响结果，不据此宣称帧率提升。首帧单样本 1889.4 / 1544.3 ms 有缓存与着色器状态差异，也不用于宣称加载提速。解码脚本约 2.6 MiB，首次渲染仍存在约 1 秒长任务。

模型真实调用覆盖职场举杯、家庭相亲和办公室加班，前后各一次，均单次生成通过校验：

| 场景 | 基线等待 | 优化后等待 | 基线输入字符 | 优化后输入字符 |
|---|---:|---:|---:|---:|
| 职场 | 3667 ms | 4507 ms | 10,221 | 10,020 |
| 家庭 | 4010 ms | 4404 ms | 10,171 | 9,964 |
| 办公室 | 5012 ms | 4499 ms | 11,085 | 10,884 |

字符数是请求的 system / messages 序列化长度，不是 token 数。开场少历史时节省有限；11 次玩家发言夹具的历史部分缩小超过 20%，仍保留每句原话、插话、当时位置和动作记录。真实样本不能证明模型等待稳定缩短；优化后仍约 4–5 秒。家庭样本仍有虚构先前转述的语义问题，沿用自由输入盲测待办，不将结构通过等同于剧情正确。

## 实现与边界

- 只对显式标记的静态饭桌 / 椅子 / 房间陈设合批。透明材质、物理材质、人物骨架及交互物件各自保留。合批按材质与阴影属性分组，销毁时只释放新几何，不释放借用材质。
- 标签复用投影向量、缓存遮挡区与尺寸；ResizeObserver / 结构变化使缓存失效。投影最多 30 次 / 秒，稳定位置不重复写样式。
- 开场、完成、面板与后台使用按需绘制；相机切换仍请求过渡帧。剧情帧循环在隐藏页 / 面板停止，UI 只接收阶段、动作与标签变化。
- 视线收敛的微小误差不刷新整个 UI，真实存档仍读取精确可变状态。位置 / 动画写入合并到最多每 500 ms 一次；文字、转录、视角、场景及状态变化立即保存，隐藏 / 离开 / 卸载强制刷新，损坏存档取消待写。
- 初始像素比上限桌面 1.5、窄屏 1.25；持续低帧率时可降至 0.75，连续三个高帧率窗口才逐步恢复。偶发长帧与启动准备不触发降级，不改人物几何。
- 进入 `/3d` 后并行请求界面和场景文件；首页依旧只用静态预览。BYOK 导演与浏览器模型实现到实际发送时加载。仅生成当前场景的装饰画纹理。
- 模型只生成台词 / 反应 / 剧情信息，旁白始终从已校验的可见动作派生。历史传输去掉重复动画字段，原存档 / 转录格式不变，当前发言仍在输入最后，保持两次尝试上限与严格验证。

按需渲染与像素比机制参考 [R3F 官方说明](https://r3f.docs.pmnd.rs/advanced/scaling-performance)。首次着色器异步准备的实验没有进入交付：预览连接中断后无法验证这一启动路径，因此保留已验证的 Canvas 创建流程。
