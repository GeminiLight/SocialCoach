# 手机模型输入与反馈入口复核

2026-10-09，用户反馈接入页看起来只能用 `gpt-4.1-mini`，并指出手机首页没有反馈入口。

## 判断与修订

- 主站 WebKit 手机视口、魔搭公开嵌入页的原输入框都允许修改模型名，没有复现字段锁死。问题不能直接归因于 readonly 或禁用状态；原界面会自动填入示例 ID，缺少清空操作，并把兼容 API 地址折叠，容易误解为固定选择。
- 新配置只用占位提示展示示例，不自动选择模型；保留已保存的个人模型。模型名可输入 / 粘贴，新增一键清空并保持输入焦点；API 地址直接可见，标签与说明分别关联，手机输入采用 16px 字号和关闭自动纠正 / 自动大写。
- 首页反馈原来依赖仅桌面显示的浮动入口。手机首页现在在 GitHub 旁提供文字“反馈”，触控区域至少 44×44px；设置页、对话中和桌面原入口保留，首页入口位于正常页面布局内。

## 验证

- Chromium / WebKit，375px / 1440px，中英与明暗：16 组浏览器组合通过，覆盖清空后逐字输入、自定义 ID 保存与复盘模型默认同源、可见 API 地址、反馈入口及受控提交。
- 反馈 POST 为隔离测试桩，没有向团队提交真实反馈；验证请求没有附带对话或模型密钥。
- 模型可用性浏览器脚本 36 项检查通过，包括失败恢复、取消、格式 / 强弱模型配置和自动无障碍检查。脚本比较实际水合后的档案，按现有背景确认流程测试生成门控。
- 65 项核心与 256 项 3D 检查、代码规范 / 类型和正式构建通过。该任务没有修改共享模型、个人已保存配置或反馈接口。

边界：WebKit 与手机视口不能替代真实 iPhone 微信内核验；用户报告的“不能输入”硬故障未在本次可用环境中复现。本次修订改善可发现性、清空与输入交互，不宣称已定位某个微信版本的内核问题。

Skill evolution：无需修改技能；该经验按本仓库入口与验收记录维护。
