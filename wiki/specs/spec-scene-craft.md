# 现有场景的可玩剧情

状态：核心实现与模型回放已完成，网页连续试玩待补验。范围是主站五类 3D 空间的十个开局、文字角色扮演和自定义排练的共同剧情标准。鱼头转向 / 倒酒仍见 [饭桌文化方案](./spec-3d-table-culture.md)，不冒充本次已实现。

## 产品要求

用户要愿意接下一句，因自己的决定看到不同后续。开场直接进入具体冲突；守住边界后有后果、部分成功后有下一层协商、失败后能修复。高潮来自有代价的关键决定，不靠所有 NPC 一直敌对或随机突发消息。没有真实用户留存数据时，不声称“已证明上瘾”。

## Fiction

以下为 SocialCoach 原创虚构剧情设计，来源为 2026-10-04 用户对现有剧情的改进要求；不是现实人物事实、地域礼仪规范或标准答案。

| 开局 | 可发展的关键冲突 | 可回应的决定 |
|---|---|---|
| 职场敬酒 | 表示尊重 → 酒与交付分开 → 条件和测试 | 陈总如何向客户表述承诺 |
| 职场日期 | 公开保证 → 缩范围 → 验证与责任 | 谁承担有条件的交付口径 |
| 家庭介绍 | 看 / 加 / 见分开 → 转述拒绝 → 关心与安排分开 | 大姨具体怎样回介绍人 |
| 家庭隐私 | 当众追问 → 未获许可的转述 → 补救 | 哪些消息可分享、转述前怎样征求同意 |
| 校园功劳 | 执行标签 → 具体贡献 → 每人核对 | 文案由谁修改、谁确认才能发布 |
| 校园任务 | 三项打包 → 本人容量 → 仍无人接的部分 | 周五做什么、谁负责、怎样交接 |
| 电梯隐私 | 离职猜测 → 管理需要 → 听众与传闻 | 正式工作更新与私人谈话的边界 |
| 电梯甩锅 | 无证据归因 → 交接事实 → 临时报法 | 现在能报告什么、核实后如何更正 |
| 办公室加活 | 顺手打包 → 邮件所需 → 数据可信度 | 18:30 发什么、由谁确认未完成部分 |
| 办公室打断 | 要求发言 → 具体关键点 → 未核数据 | 发言被听见以后，主管怎样决定方案 |

## 实现边界

- 共用 `scene-craft.ts` 注入文字角色扮演与 3D；排练创作同样要求具体冲突与可部分协商的立场。现有 58 个文字场景的运行时统一生效，不新增无出处语料。
- `arcs.ts` 每个 3D 开局四个条件式机会、人物口吻与开放结局。不是固定四阶段，更不是每过几轮自动插剧情；先回答当前话，再判断是否有适用转折。
- `story.beat?` 仅描述这轮实际玩的转折，不是达成度、评价或同意证据。限定当前开局 ID、存入原有设备档案、传给下一轮模型。旧档没有此字段仍可继续，不补写不存在的过去。
- 公开资料保持开局事实；任何新时间 / 范围 / 分工只能作为提议。台词、插话、动作和用户承诺各自独立，不把举杯、关门或举手当成功。
- 不增加按人物分别生成的请求、常驻面板、评分或账号；保留原有格式重试 / 场景修复。保留 12 回合段落、累计 24 回合和用户主动复盘 / 续聊。

## 验收

核心模型回放与工程检查见 [评审](../reviews/review-2026-10-04-scene-craft.md)；网页点击 / 连续试玩受当前浏览器连接异常影响，未标通过。

1. 十个开局均有中文多轮模型回放，含不同对象、拒绝 / 质问 / 提议 / 修复 / 未知证据 / 后续协商；不得重复起点或未经用户决定结束。
2. 五类空间额外覆盖不标准说法和英文；语义审阅核对当前回应、条件变化、事实、身份和各自承诺，不把结构通过当作“好玩”。
3. 至少一个跨段继续的实际模型轨迹；长期承诺与拒绝不能被下一段重置。
4. 单元检查旧档兼容、转折交叉校验、模型修复、历史保存与不同语言。实际网页核对短开场、换开局、继续与历史，不重引入按钮拥挤或布局跳动。
5. 发布后核对主站与国内镜像的代码 / 静态资源；真实用户吸引力与留存仍需后续玩家验证。
