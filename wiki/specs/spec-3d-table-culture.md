# SocialCoach 3D：鱼头该对着谁？

状态：产品化方案完成，关卡、动作与传播素材待实现 / 试玩。本文记录拟议体验，不表示新玩法已经上线。

## 产品判断

先做一桌能连着玩的《鱼头该对着谁？》。让整鱼上桌成为第一眼的钩子，玩家动手转盘、观察人物、说话补救；随后敬酒、拒绝与真实诉求沿着同一段关系继续。第一局需要同时让用户想到“我想试”和“刚才换个说法会怎样”。

信心为中等：3D / 语音 / 转录 / 复盘已有基础，文化细节的辨认、动作的趣味和主动重玩还没有用户证据。最便宜的验证是做一个完整关卡，让 20 位外部试玩者自己进入，观察他们是否愿意再试一次；增加地域地图和大量模型资产放在这之后。

产品仍服务压力下的沟通表现。鱼的朝向、端杯和倒酒给言语增加具体情境；结果不能按喝了多少、有没有让领导满意或手腕像不像酒店服务员来判定。主要目标由玩家选择，例如照顾来宾、守住不喝酒的边界、谈清工作条件。

## 第一局：开场就把局面交给玩家

拟复用职场包间、陈总 / 林姐 / 小周和玩家四人，新增接风宴开局。陈总是主人，林姐是这次受邀的客人，小周是同事；这些是可观察的剧情事实，不能藏成猜谜答案。人物身份不按谁年龄最大或职位最高来推断。

本局借鉴威海地方志记录的上鱼习俗。开场资料写清参考范围；NPC 台词与冲突为原创虚构，不代表当地所有人。不同地区的规则另用独立文化配置，来源见 [民俗资料](../refs/dinner-customs.md)。

以下台词均为拟议原创剧情，source 为本文与 2026-10-04 用户需求；不是礼仪教材或真实案例。

| 环节 | 玩家看见 / 可以做什么 | 后续关系变化 |
|---|---|---|
| 进入现场，约 0–5 秒 | 整鱼落到转盘上。陈总：“今天给林姐接风。小陈，这条鱼你安排一下。”鱼头、座位和同桌目光清晰可见 | 首屏只提示“拖动转盘，也可以先问”。无需先读长介绍或回答一套设置 |
| 第一件动手的事，约 5–30 秒 | 转盘、暂时不动、询问主人、观察席位。选择姓名只是对谁说话，不会替玩家转盘 | 朝向主人：主人可说“今天请的是林姐”；朝向客人：自然接住欢迎话题；询问：主人提供可知事实。不能因为玩家没背规则就无休止羞辱或判输 |
| 一件事引出下一件事 | 玩家说欢迎话，或解释刚才的摆法。主人提议举杯，同事和客人按照各自立场回应 | 转对鱼头不等于所有矛盾消失；转错也有补救。喝茶、端酒、暂不举杯都能继续剧情 |
| 真正难接的一句 | 玩家选择茶，主人可能追问：“欢迎也得有诚意吧？”玩家可以解释、反问、请客人接话、把话题拉回项目 | 不因礼貌自动让步；也不让三个 NPC 永远同时针对玩家。各人有独立动机和已知信息 |
| 自己决定这桌谈到哪里 | 有人把欢迎话题接成项目期限：“既然今天这么高兴，下周交付就定了？”玩家继续谈、留待稍后或主动离席 | 已说过的边界、承诺与行动继续生效。举杯不构成同意期限，沉默不构成承诺 |
| 看见刚才发生了什么 | 回放鱼头方向、举杯时机和用户原话；任选一个关键点从此前另开分支 | 旧练习与复盘保留。给用户具体的重玩理由，而不是简单再随机生成一桌 |

时间是演出节奏目标，不是倒计时或强制结束条件。首轮短体验应在约一分钟内出现一个完整后果，然后允许停在此处或继续完整对话；继续沿用主站段落与续聊机制，不增加“答完三题就收工”的路径。

## 3D 真正新增的操作

转盘是第一版唯一新增的直接操控。点 / 触摸转盘边缘进入操作状态，拖动转盘；拖动期间不同时转动镜头，松手后保持原位。转盘上的鱼盘和菜一起转，固定在桌边的杯子、人物和座椅不跟着走。有人伸筷时可以先等、提醒或暂停转动，不必把礼仪变成精确角度考试。

第一人称用于感受手伸向哪里、谁正在看你；第三人称用于看清桌上方位和其他人的动作。离开座位不会把人物带走。手机没有新增常驻按钮阵列；物体近旁只出现当前动作，键盘 / 触屏提供等价的按步转动方式，无法拖动也能玩。

敬酒先复用已存在的杯子、茶杯、举杯和群体回应。倒酒安排在下一步：点瓶子选接收者，先确认对方是否要添，再控制倾斜 / 停止。手、瓶和杯口必须对齐，液面与实际倒入量同步；拒绝或收手能中断动作，不能先答应“不要添”又继续倒满。

倒酒的真实感先保证握持、腕部、瓶口、液面、收手和物件接触成立。手的朝向、端杯高低、先后顺序若作为地域习惯或服务规范展示，必须单独核对来源和适用身份。酒店员工的规范不能直接成为所有宾客的通用得分标准。

## 连续可玩：变的是关系，后果仍然讲得通

首版同一桌提供三种有明确上下文的任务：第一次跟同事赴宴、替主人照顾来宾、当客人守住自己的边界。先完成一条，再验证其余两条；选择任务后显式更新身份和席位，不仅更换标题。

第二局开始，玩家可以换一个任务或从关键点重试。NPC 会依据这次分支已经发生的事情回应；不能带着另一个分支的记忆，也不能每次开口都重新劝同一杯。人物不靠随机情绪制造难度，压力来自不同目标、未知事实和真实条件。

优先扩展的情境是：客人拒绝添酒、旁人正在夹菜时转盘、两个人各说一种规矩、敬酒时被顺带要求答应工作、有人被晾在话题外、需要提前离席。每个事件都接在前一个事件留下的状态上。事件到来要由事实触发，不能把第 N 回合固定成同一句。

拟议三条路线都允许有价值的结局：把客人照顾到、把自己的边界守住、在争执中促成具体约定。“左右逢源”可以做趣味标签，但不建立一个人人必须喜欢玩家的隐藏通关条件。“掀桌”可作为后续明确标记的喜剧彩蛋；主线先实现说清不接受的事、起身离席与其他人的可信回应。夸张演出不混进现实沟通能力评分。

地方玩法后续按具体地域 / 宴席 / 来源做小篇章。先验证威海参考桌，再考虑莱山参考桌、新女婿家宴、返乡同学聚餐。城市变体需要有内容区别：身份、称谓、规则冲突和真实诉求变了，不能只换壁纸、口音和菜色。

## 回放、复盘和重玩

复盘继续复用文字版。每条沟通评价先引用用户原话，然后关联随后确实发生的 NPC 回应；玩家改变鱼头方向、拒绝添酒、端起茶杯，只以现场记录作为补充证据。动作不是自动生成的用户台词，也不能自动完成目标。

没有发言的短体验只提供动作时间线和本桌文化来源，不生成“你很会做人”“情商低”之类评价。出现来源不确定的习俗，先显示本桌主人如何要求，不包装为统一答案。

分支重试创建新练习，保存父练习与分歧点。保留已发生的前段事实，从分歧前恢复物件、席位、对话与人物已知信息；旧报告不覆盖，新分支的模型上下文不包含未发生的旧后半段。第一版可先使用“同开局再试”，精确分歧点恢复作为后续能力，不假装已经支持时间倒流。

分享默认导出这一局的题面与虚构现场图，邀请朋友做相同开局。用户原话加入卡片前可预览和编辑，原始语音不记录 / 上传；真实公司和私密背景不自动带入。分享入口让用户自己发到小红书或抖音，不替用户自动发布。称号描述本局可核对的行为，不是人格诊断或没有分布证据的百分位。

## AI 与动画各自负责什么

| 拟议阶段 | 用户掌握的事情 | 系统自主处理的事情 | 进入下一阶段的证据 |
|---|---|---|---|
| V1 一桌闭环 | 转盘、询问、说话 / 语音确认、端杯、继续或结束 | 本地物理 / 动画与观察日志；AI 在真实行动提交或发言后生成有限 NPC 回复 | 动作与转录一致；能修复错误朝向；拒绝 / 茶杯不阻断剧情；旧档案正常 |
| V2 更完整的动作与角色 | 倒酒中止、接受 / 拒绝、换身份、重试 | 人物保持已有立场和已知信息；事件按状态选择；手部与物件按限定姿态响应 | 后续台词确实记得前段，不重复同一逼问；真实手机拖动与语音编辑可用 |
| V3 地方篇章与分支回放 | 选择文化包与目标，预览后自己分享 | 从已审核的事件池组合内容，恢复确定分支状态 | 地方内容校对完成；分支历史不串线；变化确实带来主动重玩 |

动作每帧由本地逻辑处理，不对拖动角度持续调用模型。AI 可以表达角色反应，不能替用户转鱼、斟酒、接受条件或选择结局。来源和本桌可知事实限制模型胡编；服务不可用时保留现场 / 草稿并按现有接入流程说明，不能偷偷用脚本假装真实 AI 已回答。

成本按完成一次体验计算：模型回合、格式修复、失败重试、复盘和人工校对都计入。本轮不选新模型、不假定某版本的视频能力或公布未测的单局价格。首版沿用主站模型 / BYOK，记录实际调用数、首个响应与整局等待；对同一行动去重，不给每个 NPC 单独开一轮模型调用。推广先录制真实可玩的场景。

## 实施边界与先后次序

1. **先交付一桌。** 新开局 + 可转转盘 / 鱼资产 + 三类可修复后果 + 既有敬酒 / 茶杯 / 自由接话 / 历史 / 复盘。新增文化资料能查来源。以这一桌的完整试玩决定是否扩展。
2. **再补真实动作。** 添酒与中止、持杯 / 碰杯接触、伸筷时转盘、两种身份重玩；完成实体手机交互 / 加载验证后再扩大事件。
3. **最后做系列和分享。** 两个经过核对的地方篇章、关键点重试、真实玩法短视频 / 可分享题面；多人联机、自由生成任何地区的规矩、完整手指物理和大地图都留到新的证据出现后。

现有 `drama.ts` 的 `seen` / `records` 最多两次事件，`StoryBeat` 与存档枚举也只接受旧事件。连续宴席不能仅添加几个台词或直接塞入第 3 条记录；实现时需设计有界的事件序列、行动观察与旧档案兼容，已有练习不自动进入新文化桌。实现后再更新架构 / API 文档，不能把本文当作已经改变运行时契约。

主仓库 `/3d` 是唯一实现位置。复用已验证的人物 / 包间，鱼、转盘拆分与下一步倒酒只增加必要素材；资源加载、手机帧率、HUD 高度与物体交互一起验收。独立演示仓库不作为交付条件。文案实施时使用 `L={zh,en}` / `pick()`，材质颜色仍来自 `globals.css`。

## 试玩门槛与改变方向的条件

以下是拟定门槛，不是现有数据或流量预测。第一批 20 位外部试玩者不用讲解进入；约 14 位能自行发现转盘 / 询问，12 位能讲清自己的目标以及后续因果，8 位在没有奖励催促下主动重试同桌或换任务，才扩展篇章。样本用于发现问题，不用包装成统计上显著的结论。

另外做 32 条行为回放：朝向三位 NPC 或暂不操作，共 4 种状态 × 8 种回应（询问、说明、拒酒、喝茶、改口、开玩笑、转话题、离席）。校验对象、鱼向、用户原话、承诺和事件顺序；文化内容先由熟悉当地当代饭局的试玩者校正，再与来源区分记载年代。不要求 NPC 都让步，也不按单词是否命中判成功。

风险判断：如果大家只愿意转一次鱼头，接下来便离开，先重做第一句后果和下一件事，暂停增加资产；如果“背规矩”得到好分、“问清楚 / 拒绝”只能受罚，重做评价与 NPC 条件；如果动画等待让人不想接话，先减动作长度和模型调用，再增加真实感。新模型或提示更换后重放同一批案例，查看因果与成本是否真的改善。

## 传播素材草案：15 秒留一个你想接的句子

素材需在玩法上线并验证后用实际录屏替换；现在只是脚本。source：2026-10-04 用户提出的“鱼头该对着谁”与本方案的原创虚构场景。

| 时间 | 实际玩法画面 | 字幕 / 台词草案 |
|---|---|---|
| 0–2 秒 | 整鱼近景，桌旁几道目光落过来 | “山东饭桌上，这条鱼该对着谁？” |
| 2–5 秒 | 玩家转盘，鱼头朝向主人 | 陈总：“今天请的是林姐。你这是敬谁呢？” |
| 5–9 秒 | 玩家转回、拿起茶杯，其他人逐个举杯 | “鱼转对了。这杯又怎么接？” |
| 9–12 秒 | 玩家回应后，对方继续提出条件 | 展示一次真实生成且与前文连贯的 NPC 追问，不伪造功能或一键通关 |
| 12–15 秒 | 停在仍需玩家开口的现场 | “轮到你了。来 SocialCoach 接这一句。” |

候选封面：“鱼头该对着谁？”、“我转了一下鱼头，整桌人看过来了。”、“同一桌，三个人说三种规矩。你听谁的？”地域片明确是哪种参考桌；不承诺“全国酒桌唯一正确答案”或用户现实社会关系的结果。

主站入口保持 SocialCoach 名称，以《鱼头该对着谁？》作关卡题目。拟议双语钩子为 `L('鱼头该对着谁？','Who should the fish face?')`，行动为 `L('来接这一句','Take the next line')`。全局品牌主句不在本轮改动。推广效果要看点击后是否开始、继续和重玩，评论争论不单独作为成功。
