# 通用练习策略

状态：2026-09-21 本地实现；未部署。小样本验证通过，跨情境长期评测待完成。

## 问题与边界

用户反馈的「唯一解」「角色不相容」「必须拿出量化证据」是共用链路的偏差：处方检索不验证角色权限、失败时随机绕过情境、按目标数评沟通、失败示例触发结束，以及复盘拿到了用户当时不知道的 NPC 底牌。本次不改任何具体场景或语料，不增加账号或练习记录的服务端存储。

## 机制

1. **推荐先判断可扮演的角色。** 处方技能限于用户目标，情境限于明确偏好。核心候选池经过语义匹配，比较角色、关系、权限和资源；相容者优先，不确定者在无相容项时进入候选；明确冲突需引用档案原话。没有档案时保留不确定性，不推断身份。手动选择场景仍可进入。没有合适候选时报错并指向调整偏好/排练，不随机替换。
2. **隔离模拟私有信息。** `scenarioBlock(..., "learner")` 不包含 NPC 隐藏动机、内部立场、性格设定或成功/失败模板。简报、提示、复盘用该视图；只有 NPC 模拟使用完整视图。复盘能看到对话里已经说出的事实，不拿从未透露的秘密事后打分。
3. **目标追踪与对话收尾分开。** 初始目标继续按含义追踪，但不因缺关键词、缺数据或不满足预设结果结束。提前结束需 `closure`：达成协议、边界获确认、共同暂缓、明确离场；前三种都需最新用户引文与本轮 NPC 引文，单方离场可只有 NPC 引文。回合上限、用户主动结束、可选限时模式的两次沉默仍保留。
4. **沟通质量与结果分开。** 模型对实际使用的技能输出 `ratings`，0–3 的含义是语境中的沟通效果，不是完成目标数。代码验证技能、原话和重复项后取均值生成星数；无评分证据则显示未评分，不增加熟练度。`outcome` 继续记录初始目标。拒绝、暂缓、离场都可能表达得好，也都可能表达得差。
5. **评价先有证据。** 优点、弱点、改写的原句必须匹配转录；不接受 NPC 或教练的话冒充用户话。新增开场判决引文。报告完成校验后再交给 UI，不闪现原始模型评价。引文真实性不等于语义正确，因此仍需行为评测。
6. **共用现实约束。** 模拟、提示、复盘和自定义场景规则明确区分可控制的行动与对方决定，不编造业绩、资源或权限，不把数字视为唯一证据，不要求用户替对方承担超出自身角色的责任。正当拒绝不必通过另一次加班来换取；未知的可用资源应作为条件，而不是建议中的既定事实。

## 兼容与代价

- 新 `Report.scoringVersion=2`；旧 localStorage 报告原样可读，不重算、不删数据。成长页的沟通星数不混入旧目标星数；时间线保留旧版标识。
- Feishu 匿名事件新增可选评分版本/是否可评分，以及两个对应列。无引文、档案、私有信息或评价文本进入统计。
- 托管 API 与 BYOK 都调用同一任务函数。排程多一次角色匹配调用；无简介时跳过。报告仍使用原来的流式传输协议，但正文等待验证结束后才出现。
- 当前闭合判定的代码检查的是类型与引文来源，不能独立证明一句话在语义上构成收尾。角色相容性、真实后果和评分仍由模型判断，不是训练过的新模型。
- 原始目标依然可见，预设回合上限仍会结束练习。此次没有实现无限时对话、任意分支脚本或自动修改场景事实。

## 验证

- `app/scripts/check-practice-policy.ts`：18 项确定性检查，含全部 46 个语料场景的核心约束、失败不自动收尾、无目标达成仍可高评分、取得目标仍可低评分、伪造/陈旧引文、身份冲突、未知档案、私有信息隔离、旧历史兼容、未验证内容不外流。
- `app/scripts/eval-practice-policy.ts`：真实配置模型，合成对话；职场、朋友、家庭、公共服务四种开放提问不中断，角色权限冲突过滤，对方拒绝时独立评价沟通，以及用户明确离场时正确收尾，共 7 项。中英覆盖，有限样本，不是泛化能力的统计证明。
- 既有语料检查、跨场次引文检查、匿名统计检查；TypeScript、相关 ESLint、生产构建。

扩大盲测仍在 [backlog](../85-backlog.md)。特别需要观察：跨多回合的目标变更、NPC 真实拒绝与过早离场、可用信息不足时的建议、模型对「合理边界」是否仍以说服对方为默认标准。

实测观察：即使不再把缺少某个问题列为弱点，模型仍偶尔在判决中强调「未澄清对方需求」。引文校验无法判断这种侧重点是否恰当；下一轮需用多种合理策略的成对盲测评估这类偏好，不针对单个反馈场景追加例外。
