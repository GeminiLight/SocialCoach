# 公开邀请入口的首访与恢复问题

2026-10-22。同题邀请上线检查连续发现语言、初始化和平台包装层相关问题，集中记录原因与防线。→ [完整验收与原始证据](./reviews/review-2026-10-22-scenario-invite.md)。

## 影响与修复

| 触发条件 | 用户可见影响 | 根因与修复 |
|---|---|---|
| 新设备或档案语言与邀请 URL 相反 | 首屏提示语言混用，React 418 | 共享组件从设备 / 档案取语言，服务端与客户端不一致；邀请界面统一取 URL 语言，保留原档案 |
| 损坏档案打开英文邀请 | 恢复页语言不随邀请，切换可能经过档案写入 | 恢复页识别邀请路由，通过 URL 切换语言，损坏原件保持逐字一致 |
| 国内公开包装页的手机恢复界面 | English 按钮被平台浮层遮挡，实际点击失败 | 邀请恢复页语言按钮靠左；保留真实外层浮层，用普通点击验收 |
| 首次公开页面可见后立刻打开邀请 | 弹窗在档案初始化切换时消失 | 可见 SSR 早于档案就绪；邀请按钮与开练按钮一样等待初始化完成才启用 |

## 原验收为何漏过

八组主流程先建立测试档案，页面稳定后才操作，未覆盖第一次可见即点击。最初没有断言页面异常，只看完成路径和无障碍结果。直接测试应用页面也不能证明国内包装层的点击区域可用。

## 已加入的防线

- 首访脚本在创建任何测试档案前立即打开邀请，等待真实 PNG；另覆盖新设备 / 相反语言档案四组情况。
- 八组浏览器主流程断言应用页面异常为零，语言检查包含模型不可用提示与共享弹层。
- 双站从实际公开邀请地址验证 PNG 下载，逐字节比较预览与文件；国内通过外层页面和真实 iframe，不绕开浮层。
- 损坏档案验收执行 English → 中文 → English，检查原始字符串不变；不使用强制点击。
- 失败截图、日志与首次失败原因保留，不用修复后的通过结果覆盖失败历史。

这些检查证明本次工程路径；真实手机系统分享、微信与实体相机仍需设备观察，朋友完成率与传播效果没有数据。
