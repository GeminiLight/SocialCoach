# 复盘助手交付前的体验与输出校验

同一模块在验收中暴露了多个问题，记录已采取的修正，避免下一次做报告内问答时重复。

| 现象 | 原因 / 证据边界 | 修正与验收 |
|---|---|---|
| 手机长回答把输入与发送区挤到固定重练按钮下面 | 聊天区使用固定 28rem 上限，没有给手机视口和页面底部操作留出空间 | 手机日志限 30dvh；有历史时入口定位到输入表单中央；8 个中英明暗宽度组合截图 / 扫描 |
| 部分原生点击未触发停止或发送，模拟响应随后写入 | 发送 / 停止复用控件，加上入口平滑定位和未结束的入场动画，使点击的时机与目标不稳定；不能据此认定框架缺陷 | 两种动作使用独立 key，定位立即完成，测试等待入场稳定；停止后等待输入恢复，再模拟迟到回复。中止信号与请求身份双重保护 |
| 连续追问的来源被新关键词挤出检索范围 | 只按新问题的词面排名，报告既有引用仅加低权重 | 保留报告引用，同时用上一次问答与当前问题检索；原场次上下文仍完整传入 |
| 模型把可能效果写成事实，示范混进解释，或产生不合格格式 / 引文 | prompt 的泛化约束不足，字符串多段落也出现过不合法 JSON；精确引用和来源 ID 仍需代码检验 | 收紧对未观察反应、个人事实和示范的规则；模型以段落数组输出并规范化为文本；校验失败最多一次重新生成，再完整校验，失败保留问题，不替换成另一条原话 |

教训：报告内咨询是独立于 NPC 模拟的学习通道。读取、定位、成功、失败和取消都要验收；正确的引文与来源范围只是最低条件，仍需人工检查语义。原练习转录、分数和熟练度不应被咨询改变。
