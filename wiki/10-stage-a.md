## 设计决策

| 决策点 | 选择 | 原因 | 放弃的方案 |
|---|---|---|---|
| 场景检索 | 标签过滤 + 词汇匹配打分（`lexicalScore`） | 语料只有 34 条，标签体系本身已经很强的约束；零额外依赖、零延迟、结果可解释（`RetrievalTrace` 能告诉用户「为什么是这个」） | 向量检索 / embedding —— 34 条语料上收益接近零，却引入模型调用、索引构建和不可解释的排序 |
| 约束放松 | 固定顺序 `relationship_types → difficulty → related_skills`，核心约束永不放松 | 排程必须可预测。乱序放松会静默给出偏离目标技能的场景，而用户看不出来 | 让 LLM 自己决定放松什么 —— 不可复现，且核心约束会被牺牲 |
| 模型结构化输出 | 在 prompt 里要求 JSON + 宽松解析（`extractJSON` 剥代码围栏、容忍前后散文） | 当前网关**不支持** `output_config.format`（`src/lib/llm.ts` 有注释说明） | SDK 的结构化输出 / tool use —— 网关不支持，会直接失败 |
| 对话流协议 | 自定义纯文本 `@@<characterId>` + 末尾 `@@meta` JSON | 需要边流边显示台词，同时又要结构化的目标状态。纯文本前缀能在第一个 token 就开始渲染 | ①整段 JSON —— 必须等完整响应才能解析，用户盯着空屏 ②SSE 多事件 —— 网关与 Vercel 之间多一层缓冲风险，收益仅是规范化 |
| 复盘流协议 | 先流正文，末尾 `@@final` 追加 clamp 过的完整 `Report` | 报告要 60s+，等待必须有内容（设计原则 3）；同时客户端需要可信任的结构化字段写回熟练度 | 只流正文然后再发一次请求拿 JSON —— 两次 smart model 调用，成本与延迟翻倍 |
| 流内错误 | `\n@@error\n<message>` 追加在流里，HTTP 仍 200 | 流已经开始就无法再改状态码 | 中断连接 —— 客户端只能看到网络错误，拿不到可读原因 |
| 数值可信度 | 服务端校验 + clamp（`skill` 必须在 `SKILLS` 里、`deltas` 有界非负）后才发 `@@final` | 客户端要直接把 `deltas` 写进持久化状态，不能信任模型原始输出 | 客户端校验 —— 校验逻辑会和 prompt 漂移 |
| 状态存储 | Zustand `persist` → localStorage，无服务端 | 零注册是留存前提；且练习内容涉及用户真实的私人冲突，不落库是产品承诺的一部分 | 数据库 + 账号 —— 第一道流失，且与「数据留在设备上」的对外承诺冲突 |
| 模型路由 | fast（对话/提示/排程/生成）+ smart（仅复盘） | 对话回合要快且量大；复盘是唯一需要长链条推理和证据引用的环节 | 全用 smart —— 对话延迟不可接受、成本高；全用 fast —— 复盘质量是产品护城河，不能省 |
| 双语实现 | 所有面向用户的静态文案是 `L = {zh, en}` 对象，`pick(v, lang)` 取值 | 语料条目本身就是双语内容，拆成两套 i18n 资源文件会让「一条场景」变成两个文件，无法保证同步 | i18n JSON 资源包 —— 适合 UI 字符串，不适合内容型语料 |
| 模型输出语言 | 每条 system prompt 注入 `LANG_RULE[lang]` | 用户语言必须贯穿到 NPC 台词和报告，不能只翻译 UI | 事后翻译 —— NPC 台词的口语感会被翻译抹平 |
| `custom` 场景 | `/rehearse` 生成的场景标 `custom: true`，**永不进排程池** | 排程要保证语料质量与可追溯 `source`；用户生成内容没有出处，不应被推荐给「今日练习」 | 一并进池 —— 会让排程推荐出无出处内容，破坏「建议有出处」的定位 |
| 练习页结构 | 单路由 `/practice/[id]` 三阶段（简报 → 对话 → 复盘） | 三阶段共享同一个 `Session` 对象；分成三个路由要在 URL 间搬运状态 | 三个路由 —— 状态传递复杂，且刷新会丢阶段 |
| 熟练度语义 | 明确标注为「估计」，有界非负 | 不做临床评估是产品边界；单调不减避免用户练一次反而掉分导致流失 | 允许下降的真实评分 —— 越界成评测产品，且伤留存 |

## NPC 阻力设计（产品的唯一护城河，改动需按定位问题对待）

角色三个字段共同构成阻力，缺一不可：

| 字段 | 作用 |
|---|---|
| `personality` | 逐字进 NPC prompt，决定说话方式 |
| `stance` | 他要什么，**可以与用户目标冲突** |
| `hidden` | 不主动说出口的东西，只在用户问出好问题 / 展现共情 / 建立安全感时才吐露 |

prompt 层的硬约束：不跳出角色、不提及目标或 App、不提前吐露 `hidden`、用户敌意时真实升级或退让、用户用对技能时**按比例软化而非立刻投降**、回合数达 `maxTurns` 时自然收场。
