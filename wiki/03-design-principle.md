# 设计原则

> 完整 brief 见 [`app/.impeccable.md`](../app/.impeccable.md)。本文件是给 Agent 的执行约束版本；token 的唯一来源是 [`app/src/app/globals.css`](../app/src/app/globals.css)，改色改到那里，不要在组件里写死。

## 设计哲学

**「温暖纸面 · 编辑感」**——像一本被翻旧的沟通学平装书 + 教练的手写批注。

品牌人格三个词：**温暖、坦率、沉稳**。像一位读过很多沟通学书籍、见过很多真实冲突的资深教练：不哄你，也不吓你；指出问题给证据（你的原话），给建议给出处（哪本书、哪个理论）。

**浅、深两套暖纸色，默认跟随系统。** 设置可显式覆盖；深色使用暖褐纸底，强调色提亮，大面积底色保持克制。所有中性色向暖色相偏移。（2026-09-07 与现有 `globals.css`、`.impeccable.md` 同步。）

## 字体系统

字体在 2026-09-03 至 09-04 之间反复调整过（Young Serif + Hanken → Source Serif → 回到 Hanken）。**不要在这里钉死字体名，唯一来源是 [`globals.css`](../app/src/app/globals.css) 的 `--font-sans` / `--font-display` / `--font-body`。**

| 约定 | 说明 |
|---|---|
| 组件里怎么用 | 显示文本用 `.display` 类，数字用 `.num`，小标签用 `.eyebrow`。**不要在组件里写字体名**，也不要直接引 `--font-hanken` 这类具体族名——它会被换掉 |
| 中文回落 | 由 `--font-sans` 统一携带（PingFang SC / Hiragino Sans GB / Noto Sans SC / Microsoft YaHei） |
| 对外 SVG（banner / icon） | 查看者机器上没有项目字体，**必须**用广泛可用栈（banner 用 `Georgia,'Iowan Old Style',serif`）。这是唯一允许写死字体名的地方 |

**换字体时必须同步两处**：`layout.tsx` 里 `next/font` 声明的 CSS 变量名，和 `globals.css` 里引用它的地方。只改一处会静默回落到系统字体。

### 三档断点与两个布局类

| 断点 | 纸面 `.sheet` | 底部操作条 `.bar-fixed` |
|---|---|---|
| 手机 | `max-width: var(--col)`，左右发丝边 + 内阴影，外侧露出纸纹 | `position: fixed` 居中，宽度跟随纸面，顶部渐隐到纸色 |
| ≥48rem（平板竖屏） | `max-width: 40rem` | 同步 `40rem` |
| ≥64rem（`lg` 桌面） | `max-width: none`，去掉边线与阴影，**纸面铺满窗口**，`body` 去掉纸纹 | 回到文档流（`position: static`），由各页自行安放 |

桌面不是「把手机列居中」，而是纸面铺满 + 侧栏导航 + 边注列；行长由 `--measure` 控制，不再由纸面宽度控制。

## 组件模式

四条原则，按优先级：

1. **证据先于评价** —— 任何反馈先引用用户原话，再给判断与出处。
2. **一次只做一件事** —— 每屏一个主动作，主按钮永远只有一个。
3. **等待要有内容** —— 所有 LLM 等待展示阶段化进度（诊断 → 归因 → 检索 → 生成）与教练正在做什么，不用空转圈。
4. **克制的装饰** —— 装饰只用于强化「纸面与批注」的隐喻（虚线、下划线、边注），不用于填空。

**三个记忆点**（改到相关组件时必须保住）：

| 位置 | 表现 |
|---|---|
| 对话中的目标进度 | 纸面上逐格填墨 |
| 复盘报告 | 像一页带批注的稿纸，引用原话并画线 |
| 能力成长 | 五边形雷达在纸上「晕开」 |

**已定稿（2026-09-03）**：一颗心，**竖直分色**——左半墨色 `--ink`，右半赭石 `--accent`；右上一枚**墨色四角火花**（AI）。底为 `--paper-deep` 圆角方板。

### 五条硬约束

1. **画法：先整颗画赭石，再把墨色左半 clip 盖上去。** 不要把心切成两半分别 clip——共享边抗锯齿会露底色。
2. **分色边界是竖直的。** 试过弧形「互扣」接缝，S 形摆动看起来更差，已否决。
3. **火花必须是墨色。** 赭石火花贴在赭石半边旁，32px 会融掉——已实测。
4. **maskable 必须独立文件。** 满幅构图在 Android 66% 安全区（半径 169/512）内会切掉火花与心的左右——已实测。不要给 `icon.svg` 声明 `maskable`。
5. **色值只用 `#f4efe8` / `#261d16` / `#ca592e`。** 旧版图标用的是 `#f4efe6` / `#2b2620` / `#c9683e`，全部跑出色板。

### 已知风险（已评审接受）

**中文可读作「黑心」**——左半接近纯黑的心，对应「黑心商家」「黑心棉」的成语联想。2026-09-03 评审时提出并由用户确认接受当前方案。若日后要化解，把左半从 `--ink` `#261d16` 换成 `--ink-2` `#50453d`（暖褐）即可，一行改动，不动形。

**通用教训：任何图形定稿前先用中文成语过一遍。** 这一轮六次迭代全程用英文思维评估形状，直到用户指出才发现。

## 场景封面（ScenarioCover）

**核心规则：结构由内容决定，类别只用来定颜色。**

封面内容是 `scenario.opening.text` —— 对方开口说的那句话，衬线/显示字体排在纸面上，第一个分句带场景色批注下划线，左上是说话者身份 + 角色色点。34 个场景各有不同的开场白，所以封面不可能重复；同时它做了插画做不到的事：让人知道自己要面对什么。

| 变体 | 用法 | 排版 |
|---|---|---|
| `full` | 绝对定位铺满父容器。被用在 **96px（arena 网格）到 176px（Briefing）** 两种高度上 | 居中、上下等距 `py-4`、两行截断。160px+ 时文字上方约留 49px，正好躲开调用点在 `left-4 top-4` 叠的徽章 |
| `tall` | 首页今日卡的桌面左栏（280px+） | 预留 `pt-14` 顶部空间、四行截断、19px |
| `size`（44 / 64） | 列表小图标 | **对手的头像**（`Avatar`，取自开场说话的那个角色）。文字在这个尺寸不可读，而分类也救不了：`context` 41% 是职场、主能力 50% 是 relationship-skills，按任一类别上色都会退化成同一个标记。唯一真正每个场景都不同的是「人」 |

**父容器不要再设色。** 封面自带不透明 `bg-paper-deep`；调用点曾经用 `hueColor(角色色相, 0.9, 0.05)` 铺粉彩底，已全部改为 `bg-paper-deep`（留着会在水合前闪一下糖果色）。

### 为什么废掉了原来的气泡 motif

原实现按 `context` 各配一套气泡构图，靠 seed 做微扰。三个结构性问题：

1. **`context` 分布严重倾斜**：34 个场景里 **14 个是 `workplace`**。首页「为你推荐」四张并排全是职场 → 拿到同一张图。**把结构挂在分布倾斜的类别上，必然在最常见的那一类里退化成同一张图。**
2. **扰动量太小**：位置 ±0.05、旋转 ±12°、缩放 0.88–1.14，肉眼分不出。
3. **配色取自 `character.hue`，而角色色相铺满 360°**（语料里有 hue 260/280/300/310/320）→ 薄荷绿、紫、洋红，直接违反反参考「不做紫蓝」与「低饱和向暖偏移」。

用户评价是「太同质、很 AI、无趣」。也评审过「手稿页 + 灰色文本条」方案并否决：**一排灰色圆角条会被读成骨架屏加载态。**

## 头像（Avatar / AvatarFigure）

`src/data/avatars.tsx`。**侧影剪影（cameo）**：一整条路径画出的侧面胸像，鼻梁、嘴唇、下巴、发型和朝向都在轮廓上。

### 为什么从正面头肩换成侧影

第一版是「头圆 + 肩穹」两个图元，五个维度独立组合。两个问题其实是同一个错误：

1. **头和肩从来不相连。** 逐个算过 360 种组合，头底到肩顶的间隙在 **1.4 到 4.2 单位**之间（24 单位画布），一个都没有脖子。
2. **它读起来就是操作系统的默认账号图标** —— 因为正面的头压在对称的肩上，那**就是**那个图标，块面怎么变都跑不掉。

教训不是「调参数」。策展每一个词汇表还不够，因为自由变化的是**词汇表之间的关系**，而任何一个真实组合都没有人看过。

侧影解决的是这两件事：轮廓是**一条**路径，没有可以分离的部件；而且它撞不上那个正面图标。剪影肖像本身也是纸上手艺，正落在这个产品的美学里。

中间还试过一版一体式**正面**胸像。脖子接上了，但比例错了——脖子过长过细，读起来像棒棒糖，肩膀缩在底部像一株植物。真实胸像的脖子是短的（约头高三分之一），宽度接近头宽一半。

### 约束

- **色相不随机。** 语料里每个 `Character` 带作者指定的 `hue`，生成器不碰。
- **比例是围绕一个验证过基线的固定区间，不是自由数值。** 鼻子给了空间就会变成尖喙 —— 上一版就是。`NOSE` 的区间是量过的。
- **发色两侧独立取值。** `themed()` 是镜像映射，会把「比脸深」翻成「比脸浅」，所以头发走 `huePair(hue, 0.3, 0.6)` 而不是 `hueColor`。
- **圆形裁切用 CSS 而非 `clipPath`。** `clipPath` 需要每实例唯一 id，用计数器生成会让服务端与客户端标记不一致。
- **不描述长相。** 发型是块面而不是发式主张，从名字推断外观是明确不做的事。

学习者的种子是 `learnerSeed(profile.name, settings.avatarSeed)`，「我」页面的「换一个头像」递增后者。

### 回归测试

`app/scripts/check-avatars.ts`，217 个种子。最重要的一条是**轮廓必须是单一子路径**（一个 `M`、一个 `Z`）—— 这让「头断裂」这一类 bug 结构上不可能发生，而不只是修掉了那一次。另外断言纵向次序（颅顶 < 眉 < 鼻 < 嘴 < 下巴 < 喉）、可见脖长 ≤ 2.2、无 NaN、坐标在框内、以及形状离散度 > 55%（实测 95%）与朝向均衡。

## 复盘的第一屏与对话地图

**判决先于计分。** 报告过去开在三颗星和「达成 2/3」上。那是一个分数，而分数回答的是没人问的问题；真正有意思的发现被埋在第四段，和周围所有内容一个音量。现在第一屏是一句大字判决（`Report.verdict`，27/31px display），星星与「达成 n/m」降到 20px 一行，摘要退成 15px 正文。

**对话地图把让步画出来。** `session.stanceTrail` 记了对方每回合的立场，相邻两个数的差就说明哪一句推进了、哪一句让了。一条竖条带就够扫一眼，而且**跨场次是同一张图**，习惯就长在这张图里。

一个反直觉的细节：让步那一格柱子最短，视觉上反而最不显眼，正好和意图相反。所以退让不画成「更矮的柱子」，而是从新位置到旧位置之间画一条赭石半透明带，加上旧位置的实线——**把让掉的那一段画成图形本身**。

点任意一格显示当时的原话。图上的一个标记是断言，转录才是它的证据。

## 2026-09-07 界面与交互收口

- **场景目录**：推荐区继续用场景开场白；完整列表用细分隔线组织标题、处境与两项核心技能。搜索、技能、难度集中，情境横向排列；显示结果数量，支持一键清除筛选。手机横向推荐卡使用滚动内边距，保持与正文对齐。
- **首页边注**：一周练习记录来自 `practiceDays`，不虚构活动；熟练度明确标记为估计值。没有复盘时说明完成练习后会出现什么。
- **排练表单**：显式标签、最少 8 字符提示、800 字符计数；示例只在空输入时显示，避免覆盖已写内容。等待时保留正文；生成预览后焦点移到标题。草稿限定在当前标签页。
- **主动作**：`--action = --accent-deep`；`--action-hover` 浅色为 `oklch(0.46 0.14 38)`，深色为 `oklch(0.84 0.10 46)`。搭配 `--accent-ink`，将大按钮的文字与底色拉开；装饰仍用原 `--accent`。
- **导航与品牌**：侧栏和 onboarding 共享 `BrandMark`，使用已定稿分色心的路径与全局色值。选中导航同时使用底色、字重与 `aria-current`；手机选中图标有浅赭石底。
- **弹窗**：`Sheet` 使用原生 `dialog.showModal()`，背景不可交互，Tab 在弹窗内循环，Esc 关闭后恢复触发按钮焦点。关闭状态不渲染弹窗内容，避免初始双语水合差异。遮罩为 `--overlay`；入场仅使用已有 `rise`（220ms）。
- **可访问性**：保留页面缩放；`MotionConfig reducedMotion="user"` 配合 CSS 减弱动画规则；搜索和输入有可访问名称；普通筛选和图标按钮至少 44px 高。退出对话明确区分继续、稍后继续和结束复盘，没有用户原话时解释不能复盘的原因。

### 场景配色补充（2026-09-07）

根据用户对图标、推荐封面过于单调的反馈，使用五组低饱和纸色：陶土红、赭黄、橄榄绿、灰青、玫瑰褐。`globals.css` 中 `--scene-{clay,ochre,olive,teal,rose}-{color,paper}` 是唯一色值来源，均包含 light-dark 对应值。`ScenarioCover` 根据场景图标主题选择配色，同一场景的小图标底 / 线条、封面纸底 / 色点 / 批注保持一致。冲突偏陶土、金钱与成就偏赭黄、计划协作偏橄榄、亲密关系偏玫瑰，其余偏灰青；不按职场等高频情境统一着色。色彩仅辅助区分，标题、图标和开场白仍传达内容。

### 成长手册细节（2026-09-07）

- 成长页使用导语、细分隔线与无外框累计数字建立层级；只强调练习次数，避免三个数字争抢注意力。
- 练习日历自适应铺满容器，手机显示近 12 周、桌面显示近 26 周。月份标记、苔绿已练习格和今日轮廓提供时间方向，未来日期保持空白；颜色以外保留图例与可访问名称。
- 五大能力图使用五圈等距量尺（1–5）；未估计项为空心点，只有五项齐全才连接面积，避免把缺失项误画成零。起点自评和练习后估计分别解释，不把估计包装成客观测量。
- 首次练习入口使用 `growth-invitation`，由已有赭黄纸色与卡片色混合形成浅底；反思日志用书页图标与细横线，不再重复同款空卡片。
- 目标技能保留完整行为描述，显示五格量尺与数值，提供「练这项」直达筛选后的练习场；累计变化保留正负号。目标面板用勾号和已选数量补充颜色反馈。

### 其余页面精修（2026-09-07）

- 知识库：目录减少重复技能标签，桌面选中条目使用灰青纸底；正文以同色摘要、圆形步骤编号、细分隔线区分原理与做法。案例保留情境、经过、要点结构。来源始终可见，收藏和转入练习按钮至少 44px。
- 知识库手机展开按钮提供 `aria-expanded` / `aria-controls`；收起正文使用 `inert` 和 `aria-hidden`，防止不可见内容获取焦点。收藏列表参与搜索，空结果明确提供恢复入口。
- 设置：资料页使用暖赭纸底与名字首字标记；目标使用既有能力标签。语言、主题选项有选中语义与 44px 点击高度，窄屏允许换行；资料输入有固定标签，取消后重新编辑从已保存资料开始。
- 首页 / 练习场 / 排练：统一页头分隔、推荐卡页脚、箭头入口与纸面边注。首页真实排练入口、设置资料和排练引导使用 `profile-paper` / `rehearsal-invitation` / `rehearsal-guide`，颜色混合仅定义在 globals.css。知识重点使用 `knowledge-principle` 与 `knowledge-selected`，沿用既有场景灰青 token。
