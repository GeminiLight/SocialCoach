# 3D 骨骼与资产接入复盘

## 三个关联问题

1. **转头累积**：head / neck 上一帧的展示四元数未撤销，每帧乘入导致不断转偏。撤销自己应用的增量，再交给 Mixer。
2. **坐姿被覆盖**：每帧恢复 bind pose，而恒定动画缓存认为值未变化、不重写。只撤销展示层，不恢复原始骨骼。
3. **重挂载失效**：开发 StrictMode 清理停了 action 且 uncacheRoot，第二次 setup 复用 action 时缓存绑定失效。setup 重新 play，cleanup stopAllAction，实例生命周期结束时自然回收 Mixer。

额外资产问题：左右表情合并后新增 shape key 默认值非零，导致睁不开眼；显式将所有导出形变权重归零。固定膝角令较短人物坐姿鞋底悬空，按腿长解出膝 / 踝位置，检查实际蒙皮鞋底。Image.copy 会从文件重建原尺寸，染发后必须再次缩放；否则 512 纹理回到 2K。带法线贴图的 n-gon 导出无切线，先三角化；蒙皮网格父级变换不能作为 glTF 尺度依据，提升至场景根节点。

手机视口的第三人称还暴露了镜头进入电梯口实墙的问题：仅按整个房间边界约束不足，必须按玩家位于大厅 / 轿厢分别夹取；比较两侧肩位到墙的修正量，避免镜头挤近后玩家头部挡住 NPC。真实办公室回复也暴露了模型描述“前倾 / 抱臂”而导出缺对应姿态的问题，补齐 12 个坐 / 站姿态并校验实际 GLB，而不只检查手势枚举。

## 证据

`rig-motion.test.ts` 检查 1200 帧姿态 / 视线、五次 setup-cleanup 与角色独立性；`scene-assets.test.ts` 检查实际 GLB 的中性形变、动作、内嵌纹理、父级结构、眼高和完整性。Khronos glTF Validator 对 24 文件报告 0 errors / 0 warnings（Draco 扩展与未使用属性为 informational），浏览器另验解码与动作。`verify_sources.py` 检查所有 16 人的两侧鞋底与坐 / 站姿。

## 维护

不要把物理正确性等同于人物美观。每次改网格 / 比例仍需第一人称近景、第三人称、实际握持和手机视口检查。更新导出后运行 finalize，再检查文件预算与浏览器表现；保留桌面测量条件，真实手机性能单独验收。
