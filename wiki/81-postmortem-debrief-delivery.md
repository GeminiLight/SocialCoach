# 复盘交付链路：分清模型完成、有效交付与用户阅读

本轮连续处理了复盘链路的输入、传输、截止和展示边界，按项目约定集中记录。范围和完整发布证据见 [验收](./reviews/review-2026-10-29-debrief-delivery-goals.md)；不能由这些反例倒推所有历史缺失报告的原因。

| 环节 | 失效契约 / 反例 | 修订与防回归 |
|---|---|---|
| 输入 | 无用户发言的旧记录仍生成必须引用用户原话的评分，消耗调用后失败；正常结束弹窗原已有拦截 | UI 与任务入口均判断可引用发言，任务 422 / 零调用；提供返回对话和换题 |
| 传输 | 证据核对前无首字节；异常连接缺少客户端截止，等待与模型工作混为一谈 | 先发空白、每十秒保活，非空正文后停止；不展示初稿。180 秒客户端截止及取消测试 |
| 截止 | 任务到期以底层异常传播，容易与用户取消 / 模型连接故障混淆 | 原 165 秒预算不变，到期转可恢复 504，主动取消保留原语义；不增加付费重试 |
| 展示 | 同一真实报告出现模拟阶段 0/2 与独立核对 1/2 | 报告只显示独立目标结果；沟通星数独立。人工读同一记录的所有摘要 |
| 观察 | assess 错误无法关联原会话与请求，产出 / 已读 / 落盘边界不明 | 严格匿名 assessment_stage 与请求 UUID；completed 只指有效结果抵达，异步统计也不等于已逐行读回 |

共同原因不是单一模型故障，而是不同阶段各自的“完成”没有统一边界。修复不能通过删除核对、伪造空成功、自动重复付费调用或抬高分数完成。原话、意图、原目标、设备保存状态与用户阅读分别核验。

验收保留原失败测试、完整检查、真实模型请求及界面证据。开发热更新 / 分支切换造成的取消与保存保护单列，不当成线上模型失败；先实际下载合成进度，再清理测试环境，不能绕过保存锁。

后续按版本、平台与会话追踪开始 / 完成 / 失败 / 取消，补真实手机与更多连续剧情盲评。保持原始反馈和设备映射在仓库外，不以匿名设备数代表自然用户，也不以两条成功样本声称整体可靠性或速度提升。
